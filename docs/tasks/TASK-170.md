## Сценарий A — сумма продажи

1. Открыть поле суммы/цены продажи на Redmi 14.
2. Ввести с экранной клавиатуры `100`.
3. Нажать системную стрелку вниз, чтобы скрыть клавиатуру.
4. Телефон вибрирует, а значение поля самопроизвольно становится `1004`.

Ожидается: скрытие клавиатуры не создаёт input/key event, значение остаётся `100`.

## Сценарий B — Product code

1. В Receive Flow добавить товар и открыть поле Product code.
2. Ввести с экранной клавиатуры `SS55`.
3. Нажать ту же системную стрелку вниз, чтобы скрыть клавиатуру.
4. Телефон вибрирует, а к коду добавляется символ: наблюдались `SS55Q` и `SS55И`.
5. После удаления лишнего символа и повторного скрытия клавиатуры проблема
   воспроизводится снова, иногда с другим символом.

Ожидается: Product code после скрытия клавиатуры остаётся ровно `SS55`.

## Влияние

- Цена `100` может быть сохранена или показана как `1004`.
- Product code `SS55` может превратиться в другой identity (`SS55Q`, `SS55И`) и
  привести к ошибке поиска либо созданию duplicate model.
- TASK-163 нельзя считать подтверждённой на physical Android только по существующим
  component/browser tests.
- TASK-165 mobile walkthrough остаётся заблокирован до исправления и повторной

## Результат

- Controlled Product code и числовые поля продажи больше не принимают позднее
  input-событие после blur: значение меняется только пока поле владеет фокусом.
  IME composition сохраняется, а `Enter` / `Go` / `Done` только закрывают
  клавиатуру.
- Граница применена к Receive Product code, Sale Product code, цене товара,
  total sale price и суммам mixed payments. Поэтому позднее Android-событие не
  может изменить client state или payload уже после закрытия клавиатуры.
- Regression покрывает `TR07 → TR07Q` и `100 → 1004` после blur; shared staging
  acceptance остаётся централизованной в TASK-165.
