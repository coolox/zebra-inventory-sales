# Карта документации Zebra Retail

Документация — постоянная память проекта. Она должна позволять продолжить работу в новом чате и с другой моделью без восстановления контекста из переписки.

| Документ | Назначение | Когда обновлять |
|---|---|---|
| `PROJECT_STATUS.md` | Единственная точка продолжения и текущая команда | После каждой task |
| `CURRENT_STATE.md` | Исторический snapshot раннего состояния; не routing source | Только при осознанном архивном обновлении |
| `PRODUCT.md` | Цели, роли, границы и сценарии | При изменении продукта |
| `MVP_SCOPE.md` | Точный scope первого рабочего релиза | При изменении MVP |
| `ROADMAP.md` | Этапы, приоритет и критерии готовности | После завершения или перестановки этапа |
| `ARCHITECTURE.md` | Технические границы и целевая схема | При архитектурном решении |
| `DATA_MODEL.md` | Сущности и бизнес-инварианты | При изменении предметной модели |
| `DECISIONS.md` | Принятые и ожидающие решения | Сразу после решения владельца |
| `QUESTIONS.md` | Нерешённые вопросы | После ответа или появления вопроса |
| `WORKFLOW.md` | Порядок сессий, качества и передачи контекста | При изменении процесса |
| `BOT_AUDIT.md` | Факты о существующем Telegram-боте | После нового аудита VPS |
| `UI_REVIEW.md` | Визуальные замечания и утверждённые изменения | Во время visual review |

## Статусы решений

- `Принято` — можно реализовывать без повторного вопроса.
- `Предварительно` — допустимо для demo, но нужно подтвердить до production.
- `Ожидает ответа` — архитектуру на этом решении не фиксировать.
- `Отложено` — не входит в текущий этап.
- `Отменено` — больше не использовать.

## Правило актуальности

Текущую TASK и команду брать только из начала `PROJECT_STATUS.md`. Команды внутри
completed task-файлов являются историческими. Если код расходится с документацией,
использовать приоритет источников из `AGENTS.md` и явно синхронизировать handoff.
